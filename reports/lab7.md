# Лабораторная работа №7. Развертывание на целевой машине.

## Цель работы

Познакомиться с простым сценарием подготовки целевой машины и доставки программного продукта на нее.

## Этапы выполнения работы

### Создание виртуальной машины

Согласно инструкции из работы 4 был использован Manjaro + KDE.

Была выбрана платформа виртуализации для создания машины Linux -- VirtualBox.

ВМ достаточно надежно отделена от хоста. Всего один зараженный файл может быстро распространиться по сети, причинив огромный ущерб и вызвав сбои. Использование виртуальных машин помогает разработчикам или ИТ-командам изолировать зараженные приложения или файлы, защищая хост-компьютеры от вреда и предотвращая распространение вредоносного программного обеспечения. [Источник](https://www.avast.com/c-virtual-machine#:~:text=The%20disadvantages%20of%20VMs%20are,components%20and%20cause%20unstable%20performance.).

Есть ряд потенциальных опасностей из-за наличия доступа внешнего человека к виртуальной машине. Например, утечка личных данных, потеря и снос личных (любых) данных, заражение вирусом, поломка системы. Также, теоритически, возможен вред хост-системе, например если у ВМ есть доступ к ресурсам хоста (общие папки, доступ к usb), а может подключение через общую сеть - что тоже в теории лазейка к хосту.  

Была создана ВМ без графической среды. Для этого в VirtualBox около кнопки `Запустить` нужно нажать на стрелочку и выбрать `запустить без граф. оболочки`. Однако ВМ запустилась с ней. Тогда в консоли запущенной ВМ была введена команда `sudo systemctl set-default multi-user.target`, которая переключает систему в текстовый режим загрузки — без графического интерфейса, чёрная консоль с приглашением ввести логин. 

### Настройка удаленного доступа

На ВМ был обновлен список пакетов с помощью команды `sudo pacman -Sy`. Далее установлен SSH-сервер с помощью команды `sudo pacman -S openssh --noconfirm`. Был настроен автозапуск SSH-сервера при загрузке с помощью команды `sudo systemctl enable sshd`. Далее, командой `sudo systemctl start sshd`, запущена программа sshd, процесс, который начинает слушать сетевые подключения и ждёт, когда кто-то попытается подключиться по SSH. TCP-порт — это числовой идентификатор (от 0 до 65535), используемый протоколом TCP для точной доставки данных конкретному приложению на компьютере. IP-адрес находит устройство в сети, а порт определяет, какой именно программе (браузер, почта, сервер) предназначена информация. Порты обеспечивают одновременную работу множества сетевых служб. SSH использует порт 22. 

Пробрасывание портов (Port Forwarding) — это настройка маршрутизатора (роутера), которая позволяет внешним устройствам из интернета подключаться к конкретному устройству или сервису внутри локальной сети. Это перенаправление входящего трафика с внешнего IP-адреса роутера на внутренний IP-адрес компьютера. То есть, если кто-то стучится в дверь моей хост-системы, то перебросить на ВМ. 

Была выключена ВМ. В VirtualBox на странице ВМ было нажато `Настроить -> Сеть -> Расширенные -> Проброс портов`. После нажатия на плюсик было добавлено правило:

| Имя | Протокол | Адрес хоста | Порт хоста | Адрес гостя | Порт гостя |
|:----|:---------|:------------|:-----------|:------------|:-----------|
| SSH | TCP      |             | 2222       |             | 22         |

То есть, если на хост-компьютере что-то поступает на порт 2222 по TCP, отправить это в виртуальную машину на порт 22. Правило сохранено.

Была запущена ВМ. В терминале хоста была выполнена команда `ssh yarzel@localhost -p 2222`. Она запускает SSH-клиент для подключения к виртуальной машине через проброшенный порт, где `yarzel` имя пользователя внутри ВМ, `localhost` указывает на хост, флаг `-p 2222` порт, который VirtualBox слушает на хосте и перенаправляет на порт 22 ВМ. В результате устанавилось соединение с консолью виртуальной машины. 

Чтобы подключаться к серверу по ssh без ввода пароля, нужно иметь пару: открытый (публичный) и закрытый (приватный) ключ. А затем сообщить серверу публичный ключ. Есть приватный ключ на устройстве и публичный ключ на сервере. Сервер пускает только тех, кто способен доказать владение приватным ключом, при этом сам приватный ключ никогда не передаётся по сети. 

Публичный ключ был добавлен на ВМ. Были созданы нужные папки для ключей и файл с правильными правами. 
```
mkdir -p ~/.ssh
chmod 700 ~/.ssh
touch ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys 
exit
```

Открыт блокнот с публичным ключем (команда `notepad %USERPROFILE%\.ssh\id_ed25519.pub`) и скопировано содержимое. После подключения к ВМ с помощью команды `nano ~/.ssh/authorized_keys ` и вставки скопированного ранее ключа, все стало готово. После выхода и очередной команды `ssh yarzel@localhost -p 2222` пароль запрошен не было, подключение удалось. 

Был отключен пароль. С помощью команды в ВМ `sudo nano /etc/ssh/sshd_config` был изменен файл настроек. Строка `#PasswordAuthentication yes` изменена на `PasswordAuthentication no`, то есть теперь аутентификация по паролю просто недоступна. Сервер был перезапущен с помощью `sudo systemctl restart sshd`. Далее, для проверки, была введена команда `ssh -o PreferredAuthentications=password yarzel@localhost -p 2222`, которая пытается подключиться к ВМ с помощью пароля. Вывод консоли -- запрет:
```
yarzel@localhost: Permission denied (publickey).
```
