# Лабораторная работа №7. Развертывание на целевой машине.

## Цель работы

Познакомиться с простым сценарием подготовки целевой машины и доставки программного продукта на нее.

## Этапы выполнения работы

### Создание виртуальной машины

Согласно инструкции из работы 4 был использован Manjaro + KDE.

Была выбрана платформа виртуализации для создания машины Linux -- VirtualBox.

ВМ достаточно надежно отделена от хоста. Всего один зараженный файл может быстро распространиться по сети, причинив огромный ущерб и вызвав сбои. Использование виртуальных машин помогает разработчикам или ИТ-командам изолировать зараженные приложения или файлы, защищая хост-компьютеры от вреда и предотвращая распространение вредоносного программного обеспечения. [Источник](https://www.avast.com/c-virtual-machine#:~:text=The%20disadvantages%20of%20VMs%20are,components%20and%20cause%20unstable%20performance.).

Есть ряд потенциальных опасностей из-за наличия доступа внешнего человека к виртуальной машине. Например, утечка личных данных, потеря и снос личных (любых) данных, заражение вирусом, поломка системы. Также, теоритически, возможен вред хост-системе, например если у ВМ есть доступ к ресурсам хоста (общие папки, доступ к usb), а может подключение через общую сеть - что тоже в теории лазейка к хосту.  

Была создана ВМ без графической среды. Для этого в VirtualBox около кнопки `Запустить` нужно нажать на стрелочку и выбрать `запустить без граф. оболочки`. Однако ВМ запустилась с ней. Тогда в консоли запущенной ВМ была введена команда `sudo systemctl set-default multi-user.target`, которая переключает систему в текстовый режим загрузки — без графического интерфейса, чёрная консоль с приглашением ввести логин. 

### Настройка удаленного доступа

На ВМ был обновлен список пакетов с помощью команды `sudo pacman -Sy`. Далее установлен SSH-сервер с помощью команды `sudo pacman -S openssh --noconfirm`. Был настроен автозапуск SSH-сервера при загрузке с помощью команды `sudo systemctl enable sshd`. Далее, командой `sudo systemctl start sshd`, запущена программа sshd, процесс, который начинает слушать сетевые подключения и ждёт, когда кто-то попытается подключиться по SSH. TCP-порт — это числовой идентификатор (от 0 до 65535), используемый протоколом TCP для точной доставки данных конкретному приложению на компьютере. IP-адрес находит устройство в сети, а порт определяет, какой именно программе (браузер, почта, сервер) предназначена информация. Порты обеспечивают одновременную работу множества сетевых служб. SSH использует порт 22. 

Пробрасывание портов (Port Forwarding) — это настройка маршрутизатора (роутера), которая позволяет внешним устройствам из интернета подключаться к конкретному устройству или сервису внутри локальной сети. Это перенаправление входящего трафика с внешнего IP-адреса роутера на внутренний IP-адрес компьютера. То есть, если кто-то стучится в дверь моей хост-системы, то перебросить на ВМ. 

Была выключена ВМ. В VirtualBox на странице ВМ было нажато `Настроить -> Сеть -> Расширенные -> Проброс портов`. После нажатия на плюсик было добавлено правило:

| Имя | Протокол | Адрес хоста | Порт хоста | Адрес гостя | Порт гостя |
|:----|:---------|:------------|:-----------|:------------|:-----------|
| SSH | TCP      |             | 2222       |             | 22         |

То есть, если на хост-компьютере что-то поступает на порт 2222 по TCP, отправить это в виртуальную машину на порт 22. Правило сохранено.

Была запущена ВМ. В терминале хоста была выполнена команда `ssh yarzel@localhost -p 2222`. Она запускает SSH-клиент для подключения к виртуальной машине через проброшенный порт, где `yarzel` имя пользователя внутри ВМ, `localhost` указывает на хост, флаг `-p 2222` порт, который VirtualBox слушает на хосте и перенаправляет на порт 22 ВМ. В результате устанавилось соединение с консолью виртуальной машины. 

Чтобы подключаться к серверу по ssh без ввода пароля, нужно иметь пару: открытый (публичный) и закрытый (приватный) ключ. А затем сообщить серверу публичный ключ. Есть приватный ключ на устройстве и публичный ключ на сервере. Сервер пускает только тех, кто способен доказать владение приватным ключом, при этом сам приватный ключ никогда не передаётся по сети. 

Публичный ключ был добавлен на ВМ. Были созданы нужные папки для ключей и файл с правильными правами. 
```
mkdir -p ~/.ssh
chmod 700 ~/.ssh
touch ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys 
exit
```

Открыт блокнот с публичным ключем (команда `notepad %USERPROFILE%\.ssh\id_ed25519.pub`) и скопировано содержимое. После подключения к ВМ с помощью команды `nano ~/.ssh/authorized_keys ` и вставки скопированного ранее ключа, все стало готово. После выхода и очередной команды `ssh yarzel@localhost -p 2222` пароль запрошен не было, подключение удалось. 

Был отключен пароль. С помощью команды в ВМ `sudo nano /etc/ssh/sshd_config` был изменен файл настроек. Строка `#PasswordAuthentication yes` изменена на `PasswordAuthentication no`, то есть теперь аутентификация по паролю просто недоступна. Сервер был перезапущен с помощью `sudo systemctl restart sshd`. Далее, для проверки, была введена команда `ssh -o PreferredAuthentications=password yarzel@localhost -p 2222`, которая пытается подключиться к ВМ с помощью пароля. Вывод консоли -- запрет:
```
yarzel@localhost: Permission denied (publickey).
```

### Настройка сессии для другого пользователя

Был добавлен пользователь для напарника на ВМ. Для этого были сделаны следующие действия:
  - `ssh yarzel@localhost -p 2222` -- подключиться к ВМ.
  - `sudo useradd -m -s /bin/bash nikolay` -- создать пользователя, папку /home/nikolay, и дать ему оболочку bash
  - `sudo passwd nikolay` -- установить временный пароль для нового пользователя.
  - `id nikolay` -- убедиться, что пользователь создан.
  - `ls -la /home/` -- посмотреть домашнюю директорию, в ней отобразиться новая директория пользователя. 
  - ВМ ждёт напарника.

Напарник передал его публичный ключ для подключения по ssh. Необходимо добавить его публичный ключ. После этого напарник сможет подключаться к ВМ без пароля, используя свой приватный ключ. 

Начало для напарника:
> Открой терминал
>
> Если у тебя ещё нет ключа, создай его: `ssh-keygen -t ed25519`
>    
> Покажи свой публичный ключ: `cat ~/.ssh/id_ed25519.pub`
>
> Скопируй всю строчку и отправь.

Когда был получен ключ, он был добавлен на ВМ. Шаги:
  - `ssh yarzel@localhost -p 2222` -- подключиться к ВМ.
  - `sudo mkdir -p /home/nikolay/.ssh` -- созадть папку для напарника для ssh.
  - `sudo nano /home/nikolay/.ssh/authorized_keys` -- открыть в редакторе для вставки ключа и вставить ключ напарника.
  - `sudo chown -R nikolay:nikolay /home/nikolay/.ssh` -- установить владельца папки и файла.
  - `sudo chmod 700 /home/nikolay/.ssh` -- чтобы только владелец мог как либо влиять на папку.
  - `sudo chmod 600 /home/nikolay/.ssh/authorized_keys` -- только владелец может влиять на файл.
  - `ls -la /home/nikolay/.ssh/` -- для проверки. 

Компьютеры были помещены в одну локальную сеть.
  - `ipconfig` -- узнать свой IP. Он начинется со слов `IPv4-адрес. . `. Запомнить.
  - `ping мой.ай.пи.шник` -- выполнить напарнику и ввести вычисленный ранее IP. В случае неудачи выдаст: `Request timed out`.


Открыть порт — значит разрешить входящие подключения на определённый порт через брандмауэр. Брандмауэр (firewall) — это программа или устройство, которое фильтрует сетевой трафик, решая, какие подключения разрешить, а какие запретить. Порт открывается на хосте, чтобы напарник мог подсоединиться. Порт необходимо открывать тот же, который указан в правиле проброса для ВМ (`2222`). 

Открыть и закрыть порт на Windows можно через консоль:
```
# Открыть порт 2222 для входящих TCP-подключений
netsh advfirewall firewall add rule name="SSH_for_Partner" dir=in action=allow protocol=TCP localport=2222

# Закрыть порт (удалить правило)
netsh advfirewall firewall delete rule name="SSH_for_Partner"
```
Также можно открыть порт через настройки. 
  - `Win -> Брандмауэр -> Дополнительные параметры` -- открыть Брандмауэр Windows в режиме повышенной безопасности.
  - Выбрать `раздел "правила для входящих подключений" -> создать правило -> для порта -> далее`. 
  - Выбрать `протокол TCP` и `Определенные локальные порты: 2222`.
  - Выбрать `разрешить подключение`.
  - Выбрать `Частный` -- безопасный и подходящий.
  - Дать имя `ssh-lab7`.

Закрыть порт:
  - Найти в списке `раздел "правила для входящих подключений"` правило `ssh-lab7`, далее ПКМ и удалить.

В итоге, для напарника может быть открыт, а затем через некоторое время закрыт порт для подключения. 

Когда порт открыт, напарник может ввести команду `ssh nikolay@мой.ай.пи.шник -p 2222` и благодаря добавленному ключу попасть на ВМ. 

После окончания взаимодействия и экспериментов - обязательно закрыть порт.

### Развертывание программы

Перед тем как подключаться, нужно иметь на целевой ВМ следующий набор программ:
| Программа | Зачем нужна | Команда установки (Ubuntu/Debian) | Команда установки (Manjaro/Arch) |
|-----------|-------------|-----------------------------------|----------------------------------|
| **Git** | Клонировать репозиторий | `sudo apt install git -y` | `sudo pacman -S git --noconfirm` |
| **Компилятор C/C++** | Собирать код | `sudo apt install gcc g++ -y` | `sudo pacman -S gcc --noconfirm` |
| **CMake** | Система сборки | `sudo apt install cmake -y` | `sudo pacman -S cmake --noconfirm` |
| **Make** | Запускать сборку | `sudo apt install make -y` | `sudo pacman -S make --noconfirm` |
| **gdb** | Отладка | `sudo apt install gdb -y` | `sudo pacman -S gdb --noconfirm` |

Подключиться к ВМ напарника `ssh имя_на_вм_напарника@его.ай.пи.шник -p 2222`. 

Склонировать ПАБЛИК репозиторий `git clone https://github.com/аккаунт/название_репозитория.git`. Если не паблик: нужна аутентификация - временный GitHub токен.
  1. Зайти на `GitHub -> Settings -> Developer settings -> Personal access tokens -> Tokens (classic)`
  2. Нажать «Generate new token (classic)»
  3. Настроить токен:
     - Note: `Лабораторная работа 7`
     - Expiration: `1 day`
     - Scopes: галочка `repo` (полный доступ к репозиториям)
  4. Нажать «Generate token»
  5. Сразу скопировать токе (GitHub покажет его только один раз!)

При `git clone` GitHub попросит логин и пароль, в поле Password вставить токен.

***Или***:

Через SSH.

1.  `Зайти в Settings репозитория -> Deploy keys -> Add deploy key`.
2.  Ввести название.
3.  Для клонирования ее можно снять галочку с разрешения "писать" в репозиторий(`Read only` безопаснее).

Напарник должен подключиться к своей ВМ (той, куда клонировать) и выполнить:
```
ssh-keygen -t ed25519 -C "lab_partner_key"
cat ~/.ssh/id_ed25519.pub
```
Напарник копирует ключ.

Вставить скопированный напарником ключ в поле Key на странице Deploy keys на GitHub и сохранить.

Теперь после подключения к ВМ напарника можно выполнить команду клонирования через SSH-протокол, а не HTTPS:
```
git clone git@github.com:АККАУНТ/РЕПОЗИТОРИЙ.git
```

Пароль запрошен не будет и все склонируется. 

Далее по классике:
  - `cd имя/лабы` -- перейти в папку с лабой.
  - `mkdir build && cd build` -- Создать build-папку.
  - `cmake ..`
  - `make имя-исполняемого`
  - `ctest` -- пройти тесты.
